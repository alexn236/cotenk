2. CLAUDE CODE IN DER APP (der "Claude Connector")
---------------------------------------------------

Claude Code läuft jetzt genauso wie Devin: lokal, über ACP, im
Workspace-Ordner. Es arbeitet direkt auf den Seiten, und du siehst die
Änderungen live.

So funktioniert es:
- Das Rust-Backend startet pro Agent einen eigenen Prozess. Bisher war
  "devin acp" fest eingebaut.
- Claude Code läuft über den offiziellen ACP-Adapter
  "@agentclientprotocol/claude-agent-acp" (früher
  "@zed-industries/claude-code-acp"). Ist er global installiert, startet
  er schnell. Sonst nimmt die App automatisch
  "npx -y @agentclientprotocol/claude-agent-acp"; der erste Start dauert
  dann ca. 10 Sekunden.
- Anmeldung: Es gilt der normale Claude-Login auf dem Rechner (Abo oder
  API-Key), ohne extra Key in der App. "Connect" öffnet ein Terminal
  mit "claude auth login". Der Status wird über "claude auth status"
  geprüft.
- Modelle kommen direkt von Claude Code: Default, Opus 5.5, Fable 5.1,
  Sonnet 5, Haiku 4.5.
- Unter Windows gehen beim Start von Agents keine Konsolenfenster mehr
  auf (gilt auch für Devin).

Setup für dich (einmalig):
  npm install -g @anthropic-ai/claude-code          (hast du schon)
  claude auth login                                  (bist du schon)
  npm install -g @agentclientprotocol/claude-agent-acp   (optional, schnellerer Start)

Umgebungsvariablen: CLAUDE_ACP_BIN ersetzt den Adapter-Befehl, DEVIN_CLI
wie bisher den Devin-Befehl.


3. AGENT-UX
-----------

Ziel: Man sieht immer, welcher Agent antwortet und ob er bereit ist.
Wechseln geht mit einem Klick.

- Agent-Auswahl überall, wo man einem Agent schreibt: Chat, "Ask agent"
  auf Seiten, Build with AI und Befehlspalette. Der Button zeigt

  Claude Code / Devin CLI mit Statuspunkt (grün = bereit, orange =

- Ein Chat gehört zu einem Agent. Vor der ersten Nachricht kann man
  wechseln, danach nicht mehr ("Start a new chat to switch").
- Leerer Chat: Agent-Umschalter, Status ("Claude Code · 2.1.282 · signed
  in") und bei Bedarf direkt "Connect Claude Code". Vorher gab es nur

- Der Default-Agent wird gemerkt. Solange man keinen gewählt hat, nimmt

- Chat-Liste: kleines Kürzel "claude" oder "devin" pro Chat, pulsierender

8. IDEEN – BEWUSST NICHT UMGESETZT (Entscheidung bei dir)
---------------------------------------------------------

Wichtig / Sicherheit:
- Freigaben statt Auto-Approve. Claude Code und Devin bekommen alle
  Berechtigungen automatisch. Bei Claude Code heißt das auch
  Shell-Befehle, und die sind NICHT auf den Workspace-Ordner beschränkt.
  Das ist bequem, aber ein echtes Risiko. Vorschläge:
  a) Claude im Modus "acceptEdits" starten (Dateien ok, Shell fragt
     nach), oder
  b) ein kleiner Freigabe-Dialog im Chat ("Claude möchte `npm install`
     ausführen – Erlauben / Einmal / Ablehnen").
  Ich würde b) bald machen.

Agents:
- Mehrere Agents gleichzeitig. Heute läuft app-weit immer nur ein Turn.
  Technisch geht mehr (ein Prozess pro Agent), aber der Store hat einen
  globalen Status. Nützlich, aber mehr UI (mehrere Pills usw.).
- Claude-Modi in der UI (Plan, Default, Accept edits) und
  "Reasoning effort". Beides meldet der Adapter schon, es wäre nur eine
  weitere Auswahl. Weggelassen gegen Feature-Überladung.
- Gemini CLI als dritter Agent. Seit dem Umbau ist das fast nur ein
  Eintrag in agents.ts und in Rust ("gemini --experimental-acp").
- Button "Adapter installieren" in Settings, der
  "npm i -g @agentclientprotocol/claude-agent-acp" ausführt. Heute steht
  nur der Hinweis da.
- Andere Richtung "Claude Connector": ein MCP-Server von CoTenk, damit
  Claude Code im normalen Terminal (oder claude.ai) auf Seiten und Tasks
  zugreifen kann. Solange der Workspace ein normaler Ordner ist, geht das
  auch ohne: Claude Code im Ordner ~/Documents/CoTenk starten, die SKILL.md
  liegt dort. Ein MCP-Server lohnt sich erst für Web-Nutzer ohne lokalen
  Ordner.
- Die SKILL.md im Workspace wird bei jedem Start mit der App-Version
  überschrieben. Eigene Änderungen daran gehen verloren. Alternative: nur
  schreiben, wenn die Datei fehlt oder unverändert ist.

Editor / Sync (aus dem Skill-Bericht, nicht behoben):
- Verschachtelte Listen werden flach dargestellt und beim Bearbeiten flach
  gespeichert. Die "Done:"-Notiz unter delegierten Tasks ist dadurch
  nicht eingerückt.
- Task-Chips (@owner, due:) verschwinden, wenn der Task-Text einen
  Backtick enthält.
- Embeds verlieren ihren Zustand beim Neuladen (bekannt, siehe
  PRODUKT-NOTIZEN).

Technik:
- Wird ein über npx gestarteter Adapter gestoppt, beendet Windows nur
  die npx-Hülle. Der Node-Prozess endet, weil stdin geschlossen wird;
  das sollte reichen, ist aber nicht explizit getestet. Sicherer wäre ein
  Job-Object bzw. eine Prozessgruppe.
- Unter macOS finden aus dem Finder gestartete Apps oft kein
  npm/npx/claude, weil der PATH der Shell fehlt. Falls macOS wichtig wird:
  PATH beim Start aus der Login-Shell laden (z. B. das Crate
  "fix-path-env").
- .gitattributes mit "eol=lf" für .md-Dateien. Git wandelt unter Windows
  sonst in CRLF um. Der Sync verträgt das jetzt, sauberer wäre es trotzdem.
